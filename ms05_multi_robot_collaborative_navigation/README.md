# ms05_multi_robot_collaborative_navigation

Milestone 5 — two TurtleBot3 Waffles collaborating in a multi-room world: Robot 1 maps and registers QR markers, Robot 2 localises on Robot 1's live map from those markers.

This directory is a **folder, not a ROS package** — it carries no `package.xml`. It groups the three packages that make up the milestone:

| Package | Code area | Container | Owns |
|---|---|---|---|
| [`ms05_gazebo_worlds`](ms05_gazebo_worlds/) | ros worlds | `world` | `worlds/`, `models/`, `markers/`, `tools/`, `launch/simulation.launch.py`, the Gazebo↔ROS bridges and `src/cmd_vel_relay.cpp` |
| [`ms05_qr_vision`](ms05_qr_vision/) | computer vision | `vision` | `msg/QrDetection.msg`, `scripts/qr_detector_node.py` |
| [`ms05_auto_mapping`](ms05_auto_mapping/) | automapping logic | `mapping` | `msg/QrTagRecord.msg`, `srv/`, `scripts/`, the Robot 1 mapper, the Robot 2 navigator, the QR tag database, Nav2 profiles and `launch/mission.launch.py` |

colcon discovers packages recursively, so all three build normally from the workspace root:

```bash
cd ~/ros2_ws
colcon build --packages-up-to ms05_auto_mapping
source install/setup.bash
```

## Dependency boundaries

Each package depends on its own code area only — this is what makes each one independently containerisable:

- **`ms05_gazebo_worlds`**: Gazebo (`ros_gz_sim`, `ros_gz_bridge`), `rclcpp`/`geometry_msgs` for the cmd-velocity relay, and the marker generator's `python3-qrcode` / `python3-opencv`. **No Nav2, no `slam_toolbox`, no OpenCV vision nodes.**
- **`ms05_qr_vision`**: `rclpy`, `sensor_msgs`, `geometry_msgs`, `cv_bridge`, OpenCV. **No Nav2, no `slam_toolbox`, no Gazebo.**
- **`ms05_auto_mapping`**: Nav2, `slam_toolbox`, `ms05_qr_vision` (for `QrDetection`), and `ms05_gazebo_worlds` as an `exec_depend` because `mission.launch.py` includes the simulation launch.

## Cross-package contracts

### QR payload format

Every QR marker PNG generated by `ms05_gazebo_worlds/tools/generate_qr_markers.py` encodes:

```
ms05:<room>:<index>
```

| Field | Meaning | Example |
|---|---|---|
| `ms05` | literal project namespace — a decoded string not starting with `ms05:` is not one of ours | `ms05` |
| `<room>` | room identifier exactly as listed in `ms05_gazebo_worlds/markers/qr_markers.yaml` | `01` |
| `<index>` | zero-padded marker index within that room | `00` |

Example: `ms05:01:00`. The format is self-describing, so `ms05_qr_vision` parses it directly — split on `:`, expect exactly three fields — with no lookup against the marker registry.

### Interfaces

| Type | Package | Producer | Consumer |
|---|---|---|---|
| `msg/QrDetection.msg` | `ms05_qr_vision` | `qr_detector_node.py` on `/robot1/qr/detections`, `/robot2/qr/detections` | Robot 1 mapper, Robot 2 navigator |
| `msg/QrTagRecord.msg` | `ms05_auto_mapping` | `qr_tag_database_node.py` (response of `QueryQrTag`) | Robot 2 navigator |
| `srv/RecordQrTag.srv` | `ms05_auto_mapping` | call: Robot 1 mapper → `/qr_tag_database/record_qr_tag` | `qr_tag_database_node.py` |
| `srv/QueryQrTag.srv` | `ms05_auto_mapping` | call: Robot 2 navigator → `/qr_tag_database/query_qr_tag` | `qr_tag_database_node.py` |

Database services live at **global scope** (`/qr_tag_database/*`) so nodes in both robot namespaces can reach them; the records carry map-referenced poses, which is what makes them usable across robots.

### Frames and namespaces

- Robot 1: namespace `/robot1`, frames `odom` / `base_footprint` / `base_link` prefixed with `robot1/`, TF chain `map -> odom_robot1 -> robot1/base_footprint`.
- Robot 2: namespace `/robot2`, same pattern with `robot2/`, chain `map -> odom_robot2 -> robot2/base_footprint`.
- Single shared `map` frame, published by Robot 1's `slam_toolbox`; Robot 2's AMCL subscribes to `/map` (explicit remap required inside its namespace).
- QR payload contract between `ms05_gazebo_worlds` and `ms05_qr_vision`, as specified above.

## Prerequisites

QR marker generation (in `ms05_gazebo_worlds`) needs `python3-qrcode`, and its round-trip self-check needs OpenCV:

```bash
sudo apt install python3-qrcode python3-opencv
```
